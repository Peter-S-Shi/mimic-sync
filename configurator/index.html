Mimic Sync · V1 Configurator

Build a Sync Profile visually

Choose one Source / Mimic folder, add as many Targets as needed, assign a synchronization policy to each Target, then export a JSON config and copy the ready-to-run PowerShell command.

Important: this page configures intent only. The PowerShell CLI performs the real filesystem scan, generates the actual Sync Plan, asks for Y/n confirmation, and executes changes.

1. Source / Mimic Folder

The baseline folder whose content may be added to or used to update configured Targets.

V1 uses manual entry or pasted Windows paths. The Configurator does not directly access your filesystem.

2. Targets

Each Target can use its own synchronization policy.

3. Configuration Summary

This summarizes what you configured. It is not the actual filesystem-derived Sync Plan.

4. Export

Download the profile as mimic-sync.config.json. Place it next to mimic-sync.ps1 (or change the command's -Config path), then run the CLI from the repository root.

The Configurator does not scan your folders. After you place the exported config where the command can find it, the CLI will scan the real folders, show actual ADD / UPDATE actions, ask Proceed with sync? [Y/n], then execute only after confirmation.

5. Parameter Guide

Common V1 concepts in plain language.

ConceptMeaning
SourceThe baseline folder that provides shared content.
TargetA destination folder evaluated independently against the Source.
Add OnlyAdd missing Source content, but never overwrite an existing Target item.
Update OnlyUpdate differing items that already exist in the Target, but do not introduce missing Source items.
Add + UpdateAdd missing Source content and update differing existing content.
Target-onlyContent that exists only in a Target. V1 leaves it untouched.
Sync PlanThe CLI's real filesystem-derived action list shown before any write.
-ConfigPowerShell parameter pointing to the JSON Sync Profile.
V1 does not delete Target-only content, perform mirror synchronization, classify stale/exclusive history, detect renames, or use Junction-based shared references.
